## 사용자에게 보이는 결과

가족은 방명록에 텍스트 글을 남기고 각 글 아래에서 댓글을 읽거나 답한다. 작성한 글과 댓글은 로그인한 구성원의 이름으로 저장되어 다른 가족도 다시 열거나 새로고침해 볼 수 있다. 사진 없이 글과 대화에 집중한다.

## 승인된 범위

하나의 작업 단위로 기존 방명록의 텍스트 작성·조회에 댓글 읽기·작성을 더하고, 승인된 방명록 화면 구성을 적용한다. 이미 구현된 최신 공통 헤더·하단 메뉴는 홈·준비하기·여행 스케쥴·여행 정보·방명록에서 유지한다. 다른 탭의 본문 기능은 이 작업에 포함하지 않는다.

## 관찰 가능한 수용 기준

1. 방명록의 글 작성 버튼을 누르면 현재 화면 위에 작성 창이 열린다. 로그인한 이름으로 글을 남기며 새 글은 목록 맨 위에 표시된다.
2. 제목 위의 작은 소개 문구와 제목 아래의 두 줄 소개 문구는 표시하지 않는다. 목록 위에는 현재 글 수에 맞춰 `3개의 이야기가 쌓였어요` 같은 문장을 표시한다. 댓글은 이 숫자에 포함하지 않는다. 새 글이 저장되면 숫자도 갱신된다.
3. 모든 글 바로 아래에 작성된 댓글을 항상 표시한다. 펼치기·접기 버튼은 제공하지 않는다. 댓글이 없어도 바로 입력할 수 있다.
4. 댓글은 해당 글에 연결되며 작성자와 내용을 간결한 한 줄 흐름으로 표시한다. 작성 시각과 별도 댓글 수는 표시하지 않는다. 준비하기 의견처럼 입력란 오른쪽 안에 작은 `댓글 남기기` 버튼을 배치한다. 댓글을 저장하면 그 글의 댓글 목록만 갱신된다.
5. 로그인한 가족 누구나 모든 가족의 글과 댓글을 읽고 댓글을 남길 수 있다. 로그인하지 않았거나 세션이 만료된 상태에서는 저장할 수 없다. 작성자 이름은 현재 로그인 정보로 확인한다.
6. 실제 저장 후 새로고침하거나 다른 가족으로 로그인해도 글과 댓글이 남는다. 검증 시 작성자와 조회자를 바꾸어 서로의 글과 댓글을 확인한다. 이후 구현된 홈의 방명록 새 소식과 읽음 처리 동작은 그대로 유지한다.
7. 공백만 입력하면 글과 댓글을 저장할 수 없다. 저장 중 중복 제출을 막고, 실패하면 입력한 내용을 유지하면서 재시도할 수 있다. 글 작성 창을 닫았다 다시 열 때 입력 중인 내용을 유지한다.
8. 글이 없으면 첫 이야기 안내와 작성 진입 버튼을 제공한다. 목록을 불러오지 못하면 실패 안내와 다시 불러오기 동작을 제공한다.
9. 모든 주요 탭의 공통 헤더와 하단 메뉴는 연결된 결정 계약을 따른다. 본문을 위아래로 스크롤해도 하단 메뉴의 위치가 변하지 않고 본문을 가리지 않는다.
10. 프로토타입의 예시 이름과 내용을 실제 데이터로 하드코딩하지 않는다. 상단과 작성 영역에는 실제 로그인한 구성원이 표시된다.

## 확정된 제약과 근거

- 사용자가 사진을 제외하고 텍스트와 댓글을 선택했다.
- 댓글은 글 바로 아래에서 항상 읽고 작성한다. 준비하기 의견과 같은 간소한 배치를 사용자가 승인했다.
- 공통 요소의 문구·구성과 적용 범위는 연결된 헤더·메뉴 결정 계약에서 관리한다. 방명록만의 예외를 만들지 않는다.
- 시각적 배치와 상태별 구체 표현은 승인된 프로토타입을 따른다. 검토 도구의 화면·상태·너비·테마 선택은 제품 UI가 아니다.

## 가정 — 변경 가능한 기본값

- 글은 기존처럼 최대 2,000자, 댓글은 최대 500자다.
- 글은 최신순, 한 글 안의 댓글은 작성 순서대로 오래된 댓글부터 표시한다.
- 실제 데이터는 방명록에 재진입하거나 새로고침할 때 갱신한다. 다른 기기에서 작성한 내용이 열린 화면에 자동 도착하는 실시간 갱신은 이번 범위에 포함하지 않는다.
- 프로토타입에는 외부 글꼴을 요청하지 않는 시스템 글꼴과 예시 데이터를 썼다. 제품에서는 기존 프로젝트 글꼴과 실제 로그인·저장 데이터를 사용한다.

## 범위 밖과 이유

- 사진·공감·대댓글·알림·검색 — 승인된 텍스트 글과 글별 댓글의 범위를 넘어선다.
- 글·댓글 수정과 삭제 — 제안은 있었지만 별도 요구나 승인이 없었으므로 이번 범위에는 포함하지 않는다.
- 준비하기·여행 정보의 세부 기능, 로그인 화면의 제목 변경 — 공통 헤더·메뉴 변경과 별개의 사용자 경험이다.

## 미뤄 둔 결정

없음. 범위 밖 기능이 필요해지면 별도의 변경으로 구체화한다.

## 남은 위험

- 공통 가족 암호를 아는 사람은 같은 그룹의 다른 이름으로 참여할 수 있다. 기존 가족 로그인 계약의 참여 구분 방식이다.
- 프로토타입의 댓글과 실패 재현은 메모리의 예시 동작이다. 실제 DB 저장과 접근 권한은 구현 시 검증해야 한다.

## 초안 검증 기록

- 글 작성·닫기 후 다시 열기·댓글 추가·빈 상태에서 첫 글 작성·불러오기 재시도·글과 댓글의 저장 실패 후 재시도를 agent-browser로 확인했다.
- 360·390·430·768·1200px 화면과 라이트·다크 테마를 확인했다. 714×1045 검토 화면을 포함해 본문 스크롤 전후 하단 메뉴의 위치가 바뀌지 않았고 휴대폰 모형의 앱 화면 아래에 유지됐다.
- 최종 문구를 반영한 뒤 소개 문구 삭제, 글 수 3→4 갱신, 360px에서 가로 넘침 없음과 메뉴 위치 유지를 확인했다.
- 이 저장물은 구현을 위한 승인된 화면과 계약이다. 댓글·공통 헤더의 실제 앱 구현 및 배포 결과를 의미하지 않는다.
