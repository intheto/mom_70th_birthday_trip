# 방명록 댓글 구현 검증

## 댓글 배치 간소화 검증 — 2026-11-21

- 승인된 수정 초안대로 모든 댓글을 글 아래에 항상 표시하고 펼치기·접기를 제거했다. 작성자와 내용을 간결하게 나란히 배치하고, 준비하기 의견과 같은 InputGroup 구성으로 작은 작성 버튼을 입력란 안에 배치했다.
- 자동 테스트 10개, 타입 검사, lint와 diff 검사를 통과했다. 댓글의 즉시 표시와 기존 저장 중 중복 제출 차단·실패 시 입력 유지·재시도를 확인한다.
- `next-dev-loop`의 컴파일 검사와 런타임 오류 검사가 모두 비어 있었다. 별도 agent-browser 세션의 React 트리에서도 실제 댓글 컴포넌트를 확인했다.
- 김영욱으로 검증용 글과 댓글을 작성하고 새로고침 후 유지됨을 확인했다. 김고은으로 로그인해 해당 댓글을 바로 읽고 같은 글에 댓글을 추가했다.
- 360·390·430·714px에서 가로 넘침과 댓글 숨김이 없고 하단 메뉴가 유지됐다. 390px에서 입력 영역은 46px, 작성 버튼은 32px 높이로 한 줄 안에 배치됐다.
- low 강도 자동 코드 리뷰 1회에서 명확한 기능 결함을 발견하지 못했다. 리뷰어가 수행하지 않은 브라우저·DB 확인은 위의 실제 실행 검증으로 보완했다.
- Supabase 공식 변경 기록과 JavaScript 삭제 API 문서를 다시 확인했다. SDK 2.119.2와 연결 프로젝트를 확인하고 이 검증에서 생성한 글 1개·댓글 2개·연결된 읽음 기록만 삭제했다. DB 구조와 기존 데이터는 변경하지 않았다.

검증일: 2026-11-21. Supabase 프로젝트 `biwfbbdcgvtbxuaxvzaw`, SDK 2.119.2, CLI 3.2.0, Next.js 16.4.5, agent-browser 0.43.0.

## 구현 결과

- 기존 방명록 글에 연결되는 댓글 저장·조회, 작성자 이름·시각, 글별 댓글 수, 펼치기·접기와 인라인 작성을 구현했다.
- 댓글 작성자는 서버의 로그인 세션으로 확인한다. 댓글은 최대 500자이며 공백만 있는 내용은 저장할 수 없다.
- 승인된 본문 소개 문구 삭제와 글 수 문구를 반영했다. 최신 공통 계약의 상단 탭 제목과 5개 하단 메뉴를 유지했다.
- 기존 글·홈의 새 소식·준비하기 의견은 별도로 보존한다. 댓글은 방명록 글 수에 포함하지 않는다.

## 검증 결과

- `next-dev-loop`에서 현재 체크아웃의 `/_next/mcp` 경로·컴파일 오류 없음을 확인하고, 별도 agent-browser 세션으로 실제 흐름을 검증했다. React 트리에서 구현된 화면을 확인했다.
- 테스트 글 두 개를 작성하고, 김영욱·김고은·이정희가 첫 글에 댓글을 하나씩 남겼다. 두 번째 글에는 댓글 하나를 별도로 남겼다. 세 계정 모두 새로고침 후 첫 글의 댓글 3개와 두 번째 글의 댓글 1개를 정확한 작성자·작성 순서로 확인했다.
- 댓글을 추가해도 방명록 글 수는 증가하지 않았다. 작성 창을 닫았다 다시 열었을 때 작성 중인 글이 유지됐다.
- 로그인 쿠키를 제거한 상태로 열려 있던 댓글 폼을 제출했을 때 저장이 거절되고 입력 내용이 유지됐다. DB에 해당 내용이 저장되지 않은 것을 확인했다.
- 360·390·430·714px 화면에서 가로 넘침 없이 댓글을 읽고, 본문을 스크롤해도 하단 메뉴가 화면 아래에 유지됐다.
- 홈·준비하기·여행 스케쥴·여행 정보의 기존 경로에 정상 진입했다.
- 자동 테스트 9개 통과. 새 테스트는 서버의 미로그인 저장 차단·작성자 위조 무시·빈 내용과 길이 검증·DB 실패, 화면의 중복 제출 차단·실패 시 입력 유지·재시도를 확인한다. 타입 검사·lint·`git diff --check`도 통과했다.
- low 강도 자동 코드 리뷰 1회에서 주 경로나 수용 기준을 깨는 지적이 없었다. 리뷰어의 DB·브라우저 검증은 수행되지 않아 실제 연결 검증은 이 세션에서 별도로 완료했다.

## DB와 테스트 데이터

- `guestbook_comments`에 RLS를 활성화하고 `anon`·`authenticated`의 직접 접근 권한을 차단했다. 서버 역할에는 조회·추가만 허용했다. DB 권한 조회에서 RLS 활성화와 직접 조회·추가 불가를 확인했다.
- Supabase advisors 경고는 기존 `rls_auto_enable()` 함수의 실행 권한 두 건으로, 새 댓글 테이블에 대한 경고는 없었다. 기존 [후속 기록](../../follow-ups/supabase-existing-rls-function-executable.md)을 유지한다.
- 검증 시작 전의 기존 방명록 글 4개와 댓글 0개를 기준으로 보존 여부를 확인했다. 테스트 글 2개·댓글 4개와 해당 테스트 글의 읽음 기록을 정리했고 기존 글은 모두 보존됐다.
- 사용자 이름과 암호를 사용한 임시 검증 스크립트, 연결 키와 실행 환경 파일은 Git에 포함하지 않는다.
