# 여행 스케쥴 탭

## 사용자에게 제공할 결과

로그인한 가족이 하단 메뉴에서 여행 스케쥴 화면으로 이동하고, 확정 일정이 표시될 공간임을 확인한다. 상단에는 현재 선택한 탭 이름을 표시한다.

[화면 시안](prototype.html)은 이번 검토에서 요청한 탭 배치, 달력 아이콘, 상단 문구 변경을 반영한 참고 자료다. 시안 자체는 독립 실행 HTML이며 인증과 데이터 연결은 포함하지 않는다. 실제 앱에는 기존 로그인 보호와 공통 메뉴를 사용해 같은 동작을 반영한다.

## 확정된 범위

- 하단 메뉴는 `홈 → 준비하기 → 여행 스케쥴 → 여행 정보 → 방명록` 순서다.
- 새 탭의 문구는 사용자가 지정한 `여행 스케쥴`을 그대로 사용한다.
- 여행 스케쥴 탭은 달력 모양의 아이콘으로 표시한다.
- 여행 스케쥴 화면에 `확정된 일정이 표시될 예정입니다`를 표시한다.
- 로그인 이후 모든 탭의 상단 왼쪽에는 선택한 탭 이름을 표시한다. 축하 문구와 여행 부제는 표시하지 않는다.
- 모든 탭에서 상단 이름을 크고 굵은 페이지 제목으로 표시하며, 본문의 중복 탭 제목은 제거한다.
- 로그인 구성원의 이름 표시와 앱 하단에 고정된 메뉴, 본문 내부 스크롤은 유지한다.

## 관찰 가능한 수용 기준

1. 준비하기와 여행 정보 사이에 여행 스케쥴 탭이 있다.
2. 어느 탭에서나 여행 스케쥴로 이동할 수 있고 선택된 메뉴가 강조된다.
3. 여행 스케쥴의 아이콘은 격자 문자가 아닌 달력 모양으로 보인다.
4. 여행 스케쥴 화면에서 지정된 안내 문구가 정확하게 표시된다.
5. 탭을 바꾸면 상단 왼쪽 문구도 해당 탭 이름으로 바뀐다.
6. 좁은 화면에서도 다섯 메뉴의 이름이 잘리거나 가로로 넘치지 않으며, 하단 메뉴는 앱 화면 안에 유지된다.
7. 모든 탭에서 페이지 제목은 상단에 한 번만 표시되고, 본문에는 중복 제목이 없다. 상단 제목은 사용자 이름보다 크게 표시된다.

## 제약과 이유

- 일정 데이터가 없는 현재 단계에는 안내 문구만 제공한다. 일정 편집이나 등록 흐름은 추가하지 않는다.
- 현재 위치를 명확히 알 수 있도록 사용자가 요청한 탭 이름을 상단에도 표시한다.
- 기존 프로젝트 색상과 빈 상태 표현을 사용한다. HTML 시안은 실제 구현 구조를 지정하지 않는다.

## 변경 가능한 가정

- 달력 아이콘의 세부 선 모양과 여백은 실제 구현에서 기존 아이콘 체계에 맞게 조정할 수 있다.
- 시안은 네트워크 의존성을 없애기 위해 시스템 글꼴과 가상의 로그인 사용자 표시를 사용한다.
- 다른 탭은 이동과 상단 문구를 확인하기 위한 최소 맥락이다. 준비 목록, 홈 구성, 방명록 동작을 재정의하지 않는다.

## 보류와 남은 위험

- 확정 일정의 내용, 표시 형식, 등록·수정 권한은 이후 일정 기능을 설계할 때 정한다.
- 시안의 탭 이동은 실제 인증과 운영 환경의 동작을 검증한 결과가 아니다. 실제 앱의 동작 검증은 별도로 수행한다.

## 범위 밖

실제 일정 데이터 저장, 일정 편집, AI 일정 생성, 로그인 방식 변경, 다른 탭의 기능 변경은 포함하지 않는다.

## 검토 기록

시안에서 다섯 탭을 이동하며 상단 이름, 선택 표시, 달력 아이콘과 가로 넘침을 확인했다. 390·768·전체 너비 및 밝은·어두운 테마 조합을 확인했다.

실제 앱에서도 가족 로그인 후 320·390·768·1280px 너비에서 다섯 탭을 이동하며 상단 이름, 메뉴 순서와 선택 표시, 달력 아이콘, 안내 문구, 가로 넘침과 본문 스크롤 시 하단 메뉴 위치를 확인했다. `/_next/mcp`에서 컴파일·런타임 오류가 없고, React 트리에서 기존 로그인 영역의 `TripShell` 안에 일정 화면과 `Empty` 구성이 렌더링됨을 확인했다. 타입 검사·린트와 기존 테스트 3개도 통과했다.

상단 제목 확대 후 같은 네 가지 너비에서 다섯 탭을 다시 확인했다. 각 화면에 30px 상단 제목 하나만 존재하고 본문 중복 제목이 없으며, 콘텐츠와 하단 메뉴가 정상 표시된다. 미리보기도 모든 탭·세 가지 너비·두 테마에서 같은 제목 구성을 확인했다.
