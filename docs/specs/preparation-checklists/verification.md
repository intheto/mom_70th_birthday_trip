# 준비하기 구현 검증

검증일: 2026-11-21. 대상: 실제 연결된 Supabase 프로젝트 `biwfbbdcgvtbxuaxvzaw`와 로컬 Next.js 앱 `http://localhost:3002`.

## 구현 범위

공동 4항목, 가족 2항목, 개별 2항목과 공동 의견 5주제를 구현했다. 브라우저에서 DB에 직접 접근하지 않고 서버가 가족 세션·구성원을 확인한다. 가족 체크 권한은 이번 구현 시작 시 사용자가 확정한 대로 같은 가족 구성원 모두에게 부여했다.

완료 상태는 `preparation_shared_checks`, `preparation_family_checks`, `preparation_personal_checks`에 각각 저장하며 충돌 키는 항목, 가족+항목, 구성원+항목이다. 의견은 `preparation_comments`의 주제로 분리한다. 서버 공개 진입점 `features/preparation/server.ts`의 `getPreparationProgress()`는 홈에서 사용할 공동·가족·개인 완료 수와 전체 수를 계산한다. 현재 기준 전체 수는 각각 4·6·20이다. 홈 화면의 표시는 이번 변경에 포함하지 않았다.

## 자동 검증

- `bun run typecheck`: 통과.
- `bun run lint`: 통과.
- `bun run test`: 기존 테스트 2파일, 3개 통과.
- `bun run build`: Next.js 16.4.5 Turbopack 프로덕션 빌드 통과.
- `/_next/mcp`: 대상 프로젝트 경로 확인, 경로 목록·컴파일 검사 통과. 최종 `get_errors`의 설정·세션 오류 없음.
- Supabase CLI 3.2.0으로 마이그레이션 dry-run 후 적용 완료, 원격 타입 재생성. 실제 SDK는 2.119.2.
- 새 테이블 4개 모두 RLS 활성화, `anon`·`authenticated` 읽기 권한 없음 확인.
- Supabase security advisors의 기존 `rls_auto_enable()` 경고 2개는 기존 후속 과제 `docs/follow-ups/supabase-existing-rls-function-executable.md`에 해당하며 이번 테이블에 대한 새 경고는 없었다.

## 실제 브라우저·DB 흐름

`next-dev-loop`에 따라 `/_next/mcp`와 `agent-browser`를 사용했다. React 컴포넌트 트리도 수집했다. 검증 전용 단기 서버 세션으로 김영욱·류낭·김고은의 접속 상태를 전환했으며 가족 암호와 실제 사용자 세션은 변경하지 않았다.

- 김영욱으로 항공편 완료 저장, 새로고침·다른 구성원 접속 후 동일한 완료 상태 확인.
- 류낭·김고은에게 공동 체크박스가 읽기 전용으로 표시되는 것을 확인. 류낭이 UI를 우회해 공동 체크 서버 액션을 직접 요청해도 저장 거부.
- 김영욱이 상비약 완료 → 같은 가족 류낭에게 완료 표시 → 류낭이 해제 가능. 딸래미 가족 김고은에게는 별도 미완료 상태 표시.
- 김영욱이 여권 완료 → 김영욱에게 유지되고 류낭·김고은에게는 미완료 표시.
- 김영욱의 장소 의견과 김고은의 음식 의견을 각각 작성. 새로고침 후 작성자·내용 유지, 장소를 열었을 때 음식 의견은 보이지 않음 확인.
- 비어 있는 의견의 저장 버튼 비활성화 확인. 잘못된 범위, 해당 범위에 속하지 않는 항목의 서버 액션 요청 거부 확인.
- 쿠키 제거 후 직접 서버 액션 요청은 저장 거부, 준비하기 접속은 로그인으로 이동.
- 리뷰 이후 홈 → 준비하기 이동, 체크 상태 조회와 최종 컴파일·런타임 오류 없음 확인.

## 화면 확인

390×844, 1280×900에서 세 섹션의 좌우 기준선 일치, 가로 넘침 없음, 하단 메뉴가 앱 화면 하단에 고정됨을 확인했다. 모바일 실화면도 확인했다. 체크박스 20px, 항목별 이모지, 의견 접기·펼치기, 가족·개별 소형 카드 구성과 현황 수치 미표시를 확인했다. 공통 헤더·하단 메뉴는 현재 결정 계약에 따라 탭 제목과 5개 메뉴를 유지한다.

## 코드 리뷰와 정리

`codex review`에 `model_reasoning_effort=low`를 명시해 코드·SQL을 1회 검토했다. 서버 인증·권한, 가족·개인 분리, upsert 키, 의견 주제 분리와 시안 구성에서 수용 기준·주 경로를 깨는 지적 없음. 리뷰는 정적 검사였으며 실제 런타임·DB 증거는 위 별도 검증으로 보완했다. 재리뷰는 하지 않았다.

테스트로 변경한 체크 상태는 검증 전 상태로 복구했고, 생성한 의견과 단기 세션을 삭제했다. 다른 작업의 `docs/specs/home-dashboard/`는 수정·커밋하지 않았다.

## 의견 상시 표시와 입력란 축소 변경

2026-11-21 사용자 화면 검토 요청에 따라 접기·펼치기를 제거했다. 기존 의견은 항목 아래에 바로 표시하고, 장소·음식은 별도 제목 아래 항상 표시한다. 작성자와 내용을 한 행으로 배치하고 입력란과 등록 버튼은 InputGroup으로 결합했다.

실제 브라우저 320·390·1280px 폭에서 의견의 기본 표시, 46px 기본 작성 영역, 버튼 포함 여부와 가로 넘침 없음을 확인했다. 긴 입력에서 입력란이 늘어나고, 새 의견 저장·새로고침 후 표시되는 것도 확인했다. 빈 입력은 버튼만 비활성화하고 입력란은 계속 활성 상태다. 기존 뉴스 의견의 ID·읽음 식별자는 유지했다. 검증용 의견과 임시 세션은 삭제했다. 타입 검사·린트 및 Next.js 컴파일·런타임 오류 검사는 통과했다.
