## 사용자에게 보이는 결과와 범위

2026-11-21 사용자는 아이디에이션에 앞서 실제 로그인과 DB 연결을 완성하고 방명록 저장까지 구현하도록 요청했다. 등록된 가족 10명은 본인 이름과 해당 가족의 지정 암호로 홈에 들어간다. 홈과 방명록에서 로그인한 이름을 보고, 방명록에 글을 남기면 다른 가족도 같은 글을 읽는다.

## 수용 기준

1. 10명 모두 본인 가족 암호로 로그인하며 다른 가족 암호와 잘못된 암호는 거절된다. 앞자리 0을 보존한다.
2. 로그인 성공 후 홈에 진입한다. 새로고침과 재방문 시 최초 로그인으로부터 30일 동안 같은 구성원으로 유지한다.
3. 로그아웃하거나 DB 세션이 만료되면 보호된 화면에 진입하거나 방명록을 저장할 수 없다. 만료 후 로그인 화면에서 재로그인 안내를 본다.
4. 이름·가족·암호 해시는 실제 Supabase 저장 정보로 조회한다. 암호 원문과 서버 비밀 키는 공개 코드·문서·브라우저 응답에 포함하지 않는다.
5. 방명록은 로그인한 구성원이 작성한다. 요청에 다른 이름을 넣어도 작성자 판정에 사용하지 않는다.
6. 글과 작성자·작성 시각이 DB에 저장되고 새로고침 및 다른 구성원의 로그인 후에도 남는다. 목록은 최신순이며 홈에 가장 최근 글이 보인다.
7. 저장 중 중복 제출을 막고 저장 실패 시 입력 내용을 유지한다. 빈 글은 저장하지 않는다.
8. 로그인하지 않은 브라우저는 DB의 네 테이블을 직접 조회하거나 변경할 수 없다.
9. 휴대폰에서 본문을 스크롤해도 하단의 홈·준비하기·여행 정보·방명록 메뉴가 유지된다.

## 제약과 가정

- 사용자 지정 프로젝트 `biwfbbdcgvtbxuaxvzaw`를 사용한다. 실제 암호 값은 문서에 기록하지 않는다.
- 기존 로그인 화면의 문구·그림을 유지한다.
- 이번에 위임받은 최소 방명록은 텍스트 작성과 조회다. 2,000자 제한은 변경 가능한 기본값이다.
- 준비하기·여행 정보는 구성 미확정 상태를 안내한다. 체크리스트 완료 수나 예약 정보를 실제 데이터인 것처럼 표시하지 않는다.

## 범위 밖

사진·답글·공감·수정·삭제, 체크리스트·여행 정보 본문·AI 기능은 이번 연결 검증과 저장 기능의 범위에 포함하지 않는다.

## 남은 위험과 미룬 결정

공통 암호를 아는 가족은 같은 그룹의 다른 이름을 선택할 수 있다. 이는 기존 가족 로그인 계약의 참여 구분 방식이다. 추가로 미룬 필수 결정은 없다.

## Setup before implementation

- Supabase 프로젝트 관리 접근 — DB 구조와 가족 정보를 준비하는 데 필요 — CLI에서 대상 프로젝트 조회와 SQL 실행이 성공하면 완료. 이번 작업에서 확인했다.
- 비공개 서버 실행 설정 — 서버에서 DB에 접근하는 데 필요 — `.env.local`의 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`로 직접 DB 조회가 성공하면 완료. 로컬에 설정했다. 별도 배포 환경에는 같은 이름의 서버 환경변수 설정이 필요하다.
