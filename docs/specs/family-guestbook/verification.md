# 실제 연결 검증

검증일: 2026-11-21. 대상: Supabase `biwfbbdcgvtbxuaxvzaw`, Next.js 16.4.5, Supabase SDK 2.119.2, CLI 3.2.0, agent-browser 0.43.0.

- `next-dev-loop`의 `/_next/mcp`에서 프로젝트 경로·경로 목록·컴파일 오류 없음·실행 오류 없음을 확인했다. React 트리에서 TripShell과 GuestbookCompose, 서버의 GuestbookList를 확인했다.
- 실제 브라우저에서 가족 10명 전원의 본인 가족 암호 로그인, 홈 진입, 새로고침 후 이름 유지, 로그아웃 후 보호 경로 진입 차단을 확인했다.
- 세 가족 대표 각각에 대해 다른 두 가족의 암호를 거절하는 6건을 확인했다. 별도 잘못된 암호 입력도 거절했다.
- 어머니·김영욱·김고은의 글을 실제 작성하고, 새로고침 후 재조회와 다른 가족의 조회, 홈의 최신 글 표시를 확인했다. DB 직접 조회에서 본문과 실제 작성자가 대응했다. 검증용 글은 완료 후 삭제했다.
- DB의 가족은 3그룹, 구성원은 10명이며 암호는 모두 scrypt 해시다. 세션 생성·만료 시각의 차이가 30일인 것을 확인했다.
- 검증 브라우저의 특정 세션만 DB에서 만료시킨 뒤 열어둔 작성 화면으로 제출했다. 저장이 거절되고 재로그인 안내가 표시됐다. 해당 본문의 DB 저장 결과가 0건임을 확인했다.
- 공개 키로 네 테이블에 직접 접근했을 때 비로그인 조회가 차단되는 것을 확인했다. 세션 쿠키의 HttpOnly 설정도 확인했다.
- 360×640, 390×844, 430×932, 1280×900에서 가로 넘침이 없고 본문 스크롤 후에도 하단 메뉴가 화면 아래에 유지됐다.
- `bun run lint`, `bun run typecheck`, `bun run test` 통과: 테스트 3개. `git diff --check` 통과.
- `bun run build` 통과. 홈·방명록과 보호된 메뉴가 동적 서버 경로로 빌드됐다.
- 자동 코드 리뷰는 low 강도로 1회 수행했고 주 경로를 깨는 지적은 없었다. 리뷰어 자체의 런타임 검증과 문서 조회는 제한되어 있어 실제 런타임 검증은 이 세션에서 수행했다.
- Supabase advisors에서 이번에 생성한 테이블과 별개인 기존 `rls_auto_enable()`의 실행 권한 경고 두 개를 확인했다. [후속 기록](../../follow-ups/supabase-existing-rls-function-executable.md)에 근거를 남겼다.

별도 운영 웹사이트 배포는 이번 검증에 포함하지 않았다. 외부 배포 시 서버 환경변수 두 개가 필요하다. 로컬 설정은 Git에 포함하지 않았다.

## 게시 전 재검증

2026-11-21 사용자 요청으로 404 회귀 여부와 구성원 전체의 방명록 공유를 다시 확인했다.

- 개발 서버에서 10명 모두 로그인 직후, `/home` 직접 접속, 로그인 상태로 `/` 재방문을 검증했다. 작성·조회 단계에 걸쳐 홈 진입 60회에서 404가 재현되지 않았다.
- 기존 성공 빌드를 `next start`로 별도 포트에서 실행하고 세 가족 대표의 로그인·홈·방명록 진입을 확인했다. 운영 실행 방식에서도 404는 재현되지 않아 추가 경로 수정은 하지 않았다.
- 세 가족별 독립 브라우저에서 10명이 각자 한 글씩 작성했다. DB의 본문과 작성자가 모두 일치했다.
- 조회자 10명 각각의 화면에서 작성자 10명의 글 전부를 확인했다. 100개 작성자·조회자 조합을 통과했고, 새로고침 후에도 100개 조합을 다시 확인했다. 전원의 홈에서 가장 최근 글도 확인했다.
- 재검증 시작 당시 방명록은 0건이었다. 이번 검증용 글 10건을 정확한 ID로 삭제했고, 기존 검증에 사용했던 알려진 본문도 확인했다. 이전 테스트 글은 0건이었으며, 삭제 후 남은 방명록은 0건이다.
- `lint`, `typecheck`, 테스트 3개, `git diff --check`를 다시 통과했다. 이번 재검증에서는 제품 소스를 추가로 변경하지 않았다. 기존 low 코드 리뷰 1회 결과를 유지한다.
