# 가족 로그인

## Decisions

- 접속할 때 미리 등록된 가족 구성원 중 본인을 선택하고, 소속 가족의 고정 암호를 입력한다. 이름을 직접 입력하는 방식 대신 선택 UI를 사용한다.
- 암호는 가족 단위로 지정한다. 같은 가족 구성원은 같은 암호를 사용하며, 로그인한 구성원은 선택한 본인으로 구분한다.
- 가족 로그인에는 지정된 초기 비밀번호를 계속 사용한다. 첫 로그인 시 비밀번호 변경을 요구하지 않으며, 가족이 비밀번호를 변경하는 기능도 제공하지 않는다.
- 가족과 구성원, 로그인에 필요한 정보는 Supabase에 저장한다.
- 같은 브라우저에서 로그인한 시점부터 30일 동안 로그인 상태를 유지한다. 새로고침하거나 브라우저를 닫았다 열어도 선택한 구성원으로 이용하며, 로그아웃하거나 30일이 지나면 다시 이름을 선택하고 암호를 입력한다.

## Boundaries

- 초기 대상은 사용자가 지정한 3가족 10명이다. 명단은 이 기능의 명세에 기록하며, 실제 암호 값은 공개 문서나 화면에 싣지 않는다.
- 같은 가족의 암호로 그 가족의 다른 이름을 선택할 수 있다. 개인별 비밀 암호로 본인을 증명하는 모델은 아니다.
- 비밀번호를 잊었을 때의 대응 방식은 이 결정에 포함하지 않는다.

## Why

가족 구성원이 이름과 전달받은 비밀번호로 접속하는 흐름에서 비밀번호를 다시 정하는 단계를 없애 이용 절차를 단순하게 유지한다. 사용자가 비밀번호 변경을 하지 않는 방향을 명시적으로 선택했다.

사용자가 이름 선택 UI, 가족별 공통 고정 암호, Supabase 저장을 직접 지정했다. 구성원별 참여를 구분하면서 가족 안에서는 같은 접속 정보를 공유하는 방식이다.

로그인 정보의 반복 입력을 줄이기 위해 사용자가 30일간 로그인 유지 방식을 선택했다.

## Reconsider when

- 가족이 직접 비밀번호를 관리해야 한다는 요구가 생길 때.
- 같은 가족 안에서도 다른 구성원을 선택할 수 없도록 본인을 증명해야 한다는 요구가 생길 때.

## Still-rejected alternatives

- 첫 로그인 때 비밀번호 변경을 강제하는 방식 — 접속 후 사용을 시작하기 전에 추가 절차가 필요하다.
